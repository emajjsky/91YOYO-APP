# 91YOYO App 测试策略

版本：v0.1

## 1. 目标

测试优先保护跨端共享数据、权限、弱网幂等和媒体原生行为。视觉原型能点击不等于业务完成；每个路线图阶段只有在对应自动化和真机验收通过后才能标记完成。

## 2. 测试分层

### 类型与静态检查

- `tsc --noEmit`：所有提交必跑。
- 增加 ESLint 后检查 hooks、未处理 Promise、无障碍属性和禁止 Screen 直接访问数据库/COS 的规则。
- API DTO 与客户端 mapper 一起编译，防止字段变化静默扩散。

### 单元测试

计划采用 Jest + React Native Testing Library，覆盖：

- DTO 与数据库行转换。
- Feed cursor、筛选参数和错误码映射。
- 上传状态机、重试、取消、checksum 和幂等键复用。
- 视频倍速/镜像/循环状态与音视频互斥。
- 可见性、媒体数量、正文长度等客户端验证。

原生播放器和文件选择通过接口封装后 mock，不在单测里假装验证真实解码。

### 组件/集成测试

- 登录过期后刷新会话并继续原动作。
- Feed 加载、空状态、失败重试、下拉刷新和分页去重。
- 发帖从本地文件到 `ready` 再提交；上传失败不会创建帖子。
- 点赞/收藏快速连点后 UI 与服务端最终状态一致。
- 拉黑后对方帖子和私信入口消失，直接访问也返回无权限。

网络响应使用固定 JSON fixtures；同一 fixtures 也供小程序 adapter 契约测试使用。

### 数据库与 API 权限测试

每个 migration 至少验证：

- 匿名用户只能读取 published + public 内容。
- 用户不能修改他人 profile、帖子、评论、媒体和装备。
- followers/private 可见性在直接数据库请求下仍有效。
- 非会话成员不能读取消息；被拉黑用户不能发消息。
- 点赞/收藏/关注重复写入保持一条记录，计数不漂移。
- 删除与外键策略不会暴露孤儿记录。

同时检查所有外键和权限判断列存在索引，Feed 查询用 `(published_at, id)` 游标而非深页 offset。

### 端到端测试

计划采用 Maestro 覆盖稳定业务流程：

1. 手机验证码测试账号登录并恢复会话。
2. 浏览 Feed、进入详情、点赞、收藏和评论。
3. 发布图片帖子并在个人主页看到结果。
4. 删除帖子并确认其他账号不可见。
5. 打开视频练习并切换倍速/镜像。

短信验证码在测试环境使用专用测试号码/受控 OTP，不接真实短信成本和速率限制。

## 3. 真机专项

模拟器无法代替以下测试：

- HEIC、MOV、相机拍摄、limited photo library 和 Android Photo Picker。
- 视频硬件解码、镜像、倍速、长视频发热和音画同步。
- 后台音频、锁屏控制、蓝牙耳机、来电/闹钟打断。
- 4G/Wi-Fi 切换、弱网、上传中断、App 被系统杀死后恢复。
- 推送点击、深链、通知权限拒绝和 Android 通知渠道。
- 定位权限拒绝、仅本次允许和地图坐标正确性。

最低设备矩阵：一台当前 iPhone、一台仍受支持的旧 iPhone、一台原生/接近原生 Android、一台国内主流厂商 Android。

## 4. API 契约测试

为核心 DTO 保存版本化 fixtures：`profile`, `post-image`, `post-video`, `post-audio`, `feed-page`, `api-error`。测试要求：

- App mapper 和小程序 mapper 都能读取相同 fixture。
- 未知可选字段不会导致解析失败。
- 缺失必需字段会产生稳定可诊断错误。
- 所有枚举在两端显示映射一致。
- 签名 URL 过期后能按 media ID 刷新，而不是把 URL 当主键。

## 5. CI 门槛

每个 Pull Request：App 与 server 依赖安装 → TypeScript → lint → 单元/组件测试 → 临时 PostgreSQL migration + 权限测试。合并到发布分支后构建 iOS/Android 内测包并运行 E2E 冒烟。

不以单一覆盖率数字代替关键场景。初始建议业务 service/repository 行覆盖率不低于 80%，但权限判断和上传状态机要求关键分支全部覆盖。

## 6. 发布检查

- 无 P0/P1 已知缺陷。
- 登录、Feed、发帖、播放和注销在 staging 真机通过。
- 崩溃和 API/上传/播放失败可关联 request ID。
- production 环境没有测试账号、开发 URL、数据库密码或 COS Secret 泄漏。
- 隐私文案与实际权限、SDK、采集数据一致。
