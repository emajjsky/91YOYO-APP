# Auth And Feed Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the App's local-only feed foundation with Supabase-backed phone authentication and cursor-paginated public/following feeds.

**Architecture:** Supabase Auth owns sessions and AsyncStorage persists them. A small service layer owns client configuration, auth operations, feed queries, and DTO mapping; screens consume Zustand state and never import Supabase directly. A versioned SQL migration defines the first shared tables and RLS policies.

**Tech Stack:** Expo 57, React Native 0.86, TypeScript, Zustand, Supabase JS, PostgreSQL/Supabase, Vitest for pure service tests.

**Spec:** `docs/APP_PRD.md`, `docs/ARCHITECTURE.md`, `docs/DATA_MODEL.md`, `docs/API_CONTRACT.md`

## Global Constraints

- App and mini program share the database model and JSON semantics, but not UI components.
- Public feed reads are allowed without a session; following feed and writes require authentication.
- Supabase `anon` key is the only client-side key; service role remains server-side.
- Feed pagination uses an opaque cursor in the repository API and `(published_at, id)` ordering in SQL.
- A missing local Supabase configuration must produce a recoverable setup state, not a module-load crash.
