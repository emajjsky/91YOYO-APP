# 91YOYO Mock-First App Experience Design

日期：2026-09-16  
状态：待用户最终确认  
范围：React Native App 前端体验，不包含登录、数据库、COS 或云端部署

## 1. 目标

先交付一个内容完整、交互连贯、可在 iOS 模拟器反复测试的本地 App。页面结构借鉴 X 的高密度社区信息流和 TikTok 的沉浸式视频观看方式，但不复制两者的商标、文案或品牌视觉。

本阶段使用真实感 Mock 数据和本地素材完成所有主要流程。后续接入服务端时替换 repository 实现，页面组件和交互状态不重写。

## 2. 本阶段不做

- 不继续开发手机号登录、注册和账号绑定。
- 不新增数据库表、COS 上传签名或生产 API。
- 不配置正式域名、HTTPS、短信、推送或云端环境。
- 不实现真实推荐机器学习模型；使用可解释、可测试的本地评分函数。
- 不把装备模块做成交易市场。

已部署的腾讯云基础服务保留，但前端 Mock 阶段不依赖它。

## 3. 信息架构

底部导航保持五个入口：

1. 首页：推荐流和关注流。
2. 探索：搜索、分类和相关内容发现。
3. 发布：创建文字、图片、视频或音乐动态。
4. 装备：当前用户的个人悠悠球藏品馆。
5. 我的：个人资料、动态、收藏和设置入口。

详情、视频播放器、用户主页、装备详情、装备编辑和账户设置使用根 Stack 页面，进入后隐藏底部导航。

## 4. 视觉方向

- 基础布局采用 X 式扁平信息层级：近黑背景、细分割线、紧凑作者信息、正文和四项互动栏，不使用大面积装饰卡片。
- 视频体验采用 TikTok 式全屏画面：画面占据主体，作者和说明叠加在底部，互动按钮垂直排列在右侧。
- 品牌色只用于状态：青色表示可操作或选中，粉色表示喜欢；其余以中性黑、白、灰为主。
- 文字层级优先服务扫描，不使用夸张标题。正文按系统字体缩放，按钮点击区域至少 44pt。
- 图标使用一致的矢量图标库，避免 Emoji 作为核心导航和操作图标。内容标签中的 1A-5A 可以保留文字。
- 卡片圆角不超过 8px；Feed 主体不使用悬浮卡片，依靠分隔线组织。
- iPhone 竖屏优先，同时验证小屏 iPhone SE 尺寸和常规 Android 尺寸不溢出。

## 5. 首页

### 5.1 顶部结构

顶部为固定双 Tab：`推荐`、`关注`。切换时保留各自滚动位置。

### 5.2 推荐流

推荐流混合以下来源：

- 已关注用户发布的内容。
- 与用户兴趣标签匹配的内容，例如 1A、5A、教学、音乐。
- 当前热度较高的新内容。

Mock 推荐分数：

```text
score = interestMatch * 0.40
      + freshness * 0.25
      + engagement * 0.20
      + relationship * 0.15
```

同分时按发布时间倒序。每条非关注来源的推荐内容可以显示简短推荐原因，例如“因为你喜欢 1A”，但不为关注用户内容重复显示原因。

### 5.3 关注流

只展示已关注用户的公开内容，按发布时间倒序。取消关注后，该作者的新内容立即从关注流移除。

### 5.4 Feed 内容类型

- 文字帖：作者、正文、标签和互动栏。
- 图片帖：1 张使用大图，2 张并排，3-9 张使用稳定网格并支持全屏预览。
- 视频帖：信息流中显示 4:5 或 16:9 封面；点击进入全屏视频流。
- 音乐帖：显示封面、曲名、BPM、时长和播放按钮。
- 赛事/聚会内容：显示时间、城市等结构化信息，但仍保持 Feed 外观。

互动包括评论、转发/分享、点赞和收藏。Mock 阶段全部即时更新本地状态，并在详情页、首页和个人页之间同步。

## 6. 全屏视频流

- 从视频帖进入后，以当前视频为第一条，上下滑动切换相关视频。
- 单击画面播放/暂停；右侧依次为作者头像、点赞、评论、收藏和分享。
- 底部展示作者、正文、标签、音乐信息和进度。
- 提供 `0.5x / 0.75x / 1x`、镜像和循环控制，控件展开时不遮挡系统返回按钮。
- 离开全屏页后停止视频并恢复首页原滚动位置。
- Mock 素材也必须是真正可播放的视频，不使用静态图片假装播放。

## 7. 探索

探索不是第二个首页，主要负责主动发现：

- 顶部搜索框搜索作者、正文和标签。
- 横向分类：全部、日常、音乐、教学、比赛、赛事、产品、聚会。
- 分类内容使用媒体优先的双列发现网格；没有媒体的资讯内容使用紧凑列表。
- 排序综合类别相关度、热度和新鲜度，不加入“是否关注”权重。
- 点击热门话题会进入对应筛选结果，清除搜索后恢复之前选择的分类。
- 空结果、加载和重试状态都有固定布局，不出现分类栏拉伸或纯黑空屏。

## 8. 发布

发布流程使用本地 Mock 媒体库验证完整交互：

1. 选择文字、图片、视频或音乐类型。
2. 从内置 Mock 素材选择媒体并预览。
3. 填写正文、分类、标签和可见范围。
4. 校验必填项，展示明确的行内错误。
5. 点击发布后显示本地进度，成功后写入 Mock Store。
6. 新动态立即出现在首页和个人主页。

支持保存草稿、删除已选媒体、防重复提交和取消返回确认。本阶段不调用系统相册、不上传 COS。

## 9. 装备藏品馆

装备页只表示当前用户的个人收藏：

- 顶部显示藏品数量和添加入口。
- 分类包含悠悠球、球绳、轴承/配件、奖项和其他。
- 藏品使用两列图片网格，图片必须与悠悠球领域相关。
- 支持查看详情、添加、编辑、删除、置顶、喜欢和按分类筛选。
- 新增或编辑后列表和个人页数量立即同步。
- 空分类显示空状态，分类条保持固定高度。
- 不显示价格、联系卖家、下单或交易状态。

## 10. 我的与用户主页

- 我的页面显示头像、昵称、简介、关注/粉丝/藏品数量。
- 内容 Tab 包含动态、收藏和装备，点击项目进入对应详情。
- 设置是独立 Stack 页面，进入后隐藏底部导航。
- 基本资料、兴趣标签、地区和隐私设置在 Mock Store 中可编辑并立即回显。
- 其他用户主页支持本地关注/取消关注，并影响首页关注流。

## 11. Mock 数据与素材

### 11.1 数据边界

建立统一 `mockRepository`，页面不直接导入大段数组。数据至少包括：

- 12-20 个用户，覆盖新手、选手、教练、收藏者和赛事组织者。
- 40 条以上动态，覆盖所有分类和媒体类型。
- 8 条以上可播放视频、6 条音乐内容、多个图片组。
- 15 件以上真实感悠悠球藏品。
- 评论、关注关系、兴趣标签、草稿和本地互动状态。

### 11.2 素材原则

- 优先使用许可清晰的 Wikimedia Commons、Pexels、Pixabay 或明确允许演示使用的素材。
- 下载到 `assets/mock/`，避免运行时依赖随机图片 URL。
- 图片和视频要能看出真实悠悠球、比赛、练习动作或装备，不使用电脑、麦克风、风景等无关占位图。
- `assets/mock/ATTRIBUTION.md` 记录来源、作者和许可。
- 控制尺寸，避免仓库和 App 包无必要膨胀。

## 12. 状态管理

- Zustand 按领域拆分为 Feed、用户、发布草稿和装备 Store。
- 使用本地持久化保存点赞、收藏、关注、草稿、发布内容和装备修改。
- 提供“重置演示数据”入口，便于重复验收。
- Repository 返回 Promise 并模拟短延迟、失败和分页，页面仍按真实网络状态设计。
- 所有数据对象使用稳定 ID；跨页面通过 ID 读取 Store，禁止复制一份详情 Mock。

## 13. 错误与边界状态

- 首次加载、下拉刷新、加载更多、空列表和失败重试分别展示。
- 图片或视频加载失败显示占位和重试，不导致卡片高度跳变。
- 输入达到上限时显示计数；不允许空内容或无分类发布。
- 删除、退出编辑和丢弃草稿需要二次确认。
- 点赞等乐观更新失败时回滚并给出轻量提示；Mock Repository 可以切换失败模式用于测试。

## 14. 验收标准

### 首页

- 推荐流排序可以用固定数据重复验证。
- 关注流只出现已关注作者内容。
- 点赞、收藏、关注和发布在相关页面同步。
- 图文、视频、音乐和资讯帖子均不溢出或跳动。

### 探索

- 每个分类都有相关内容；搜索和话题筛选结果正确。
- 分类少数据和无数据时布局稳定。

### 发布

- 四种内容类型均可走完本地发布流程。
- 草稿、校验、取消和防重复提交可复现。

### 装备

- 添加、编辑、删除、置顶和分类筛选均可完成。
- 个人页藏品数量同步更新。

### 视觉与设备

- iPhone 常规尺寸和小屏尺寸完成逐页截图检查。
- 页面无重叠、裁切、空白拉伸、不可点击控件或错误底部导航。
- 主要流程使用自动化单元测试和模拟器手动交互共同验证。

## 15. 实施顺序

1. 统一设计 Token、图标和 Mock 数据模型。
2. 重做首页 Feed 与本地推荐/关注逻辑。
3. 重做探索和内容筛选。
4. 完成帖子详情与全屏视频流。
5. 完成发布及本地草稿/发布闭环。
6. 完成装备藏品馆的增删改查。
7. 完成个人资料、关注关系和设置编辑。
8. 进行全页面模拟器测试、修复和最终前端验收。

用户确认本规格并完成前端验收后，才恢复登录注册、数据库、COS 和云端工作。
