# 91YOYO App 产品需求文档

版本：v0.1  
状态：App MVP 基线  
更新日期：2026-09-15

## 1. 产品目标

91YOYO App 服务悠悠球玩家的三个高频场景：看招式并跟练、记录和交流练习内容、寻找装备与同城球友。第一阶段先验证“媒体练习工具 + 垂直社区”是否形成持续使用，不用首版同时承担完整交易平台和线下活动平台的复杂度。

App 是首发主线；微信小程序后续作为低门槛访问入口。用户在任一端创建的账号、帖子、评论、收藏和个人资料，在另一端登录后应保持一致。

## 2. 目标用户

- 入门玩家：需要按 1A-5A 分类找到教学，并通过慢放和镜像跟练。
- 进阶/比赛玩家：需要发布动作视频、使用比赛伴奏、记录练习和备赛内容。
- 内容创作者与赛事组织者：需要发布教学、比赛视频、赛事与聚会信息。
- 装备玩家：需要展示收藏、浏览二手装备，并与卖家沟通。

## 3. 核心价值

1. **看得清**：视频支持慢放、镜像、拖动和重复播放，直接服务动作学习。
2. **练得顺**：比赛伴奏支持后台播放、进度记忆和 BPM 信息。
3. **交流准**：内容按花式、分类和标签组织，不被泛娱乐信息淹没。
4. **数据连续**：App 与小程序使用同一账号和内容资产，切换端不丢数据。

## 4. App MVP 范围

### 4.1 账号与个人资料

- 手机验证码注册/登录、会话恢复、退出登录和账号注销入口。
- 昵称、头像、城市、简介、擅长花式（1A-5A）编辑。
- 查看自己和其他用户的帖子、关注数、粉丝数和装备展示。
- 未登录用户可以浏览公开内容；发布、互动和私信前要求登录。

### 4.2 社区 Feed

- 首页按发布时间游标分页，支持下拉刷新和继续加载。
- 帖子支持文字及一种主要媒体组合：最多 9 图、1 个视频或 1 个音频。
- 帖子必须选择一个分类：日常分享、YOYO 音乐、招式教学、比赛视频、赛事资讯、产品资讯、聚会信息。
- 支持公开、仅关注者、仅自己三种可见性。
- 支持点赞、取消点赞、收藏、取消收藏、评论、删除自己的帖子和举报。
- 帖子详情显示完整内容和一级评论；评论回复不进入首版。

### 4.3 探索与搜索

- 按分类、花式和标签筛选公开帖子。
- 搜索用户、帖子正文和话题标签。
- 搜索结果至少分为“内容”和“用户”两个 Tab。

### 4.4 媒体练习能力

- 视频播放、暂停、拖动、全屏、`0.5x / 0.75x / 1x` 倍速、左右镜像和单段循环。
- 音频播放、暂停、拖动、后台播放、锁屏控制和上次进度恢复。
- 图片支持 1-9 张：1 张使用受限原比例大图，多图统一使用单张大图横向分页相册，不使用宫格；显示当前页码，点击后全屏浏览全部图片并支持双指缩放。
- 发布时支持系统相册/文件选择、上传进度、失败重试和发布前预览。

### 4.5 装备

MVP 保留只读装备列表和个人装备柜，只实现展示与筛选，不提供联系卖家入口。联系、装备发布、支付、担保、物流、退款与结算不属于 MVP。

## 5. MVP 之后

- 一对一私信与装备卡片消息。
- 装备发布、议价、预留和成交状态。
- Jam 地图、活动发布、报名、签到和系统日历。
- App 推送与小程序订阅消息。
- 微信快捷登录及已有手机账号绑定。
- 多语言界面、语言设置与帖子自动翻译；当前 Mock 和首轮前端验收统一使用中文。
- 交易支付、担保和售后仅在资质、风控、客服流程均具备后启动。

## 6. 明确不做

- 首版不做群聊、直播、短视频推荐算法、等级积分和虚拟货币。
- 首版不做跨帖子多层评论树。
- 首版不允许匿名发布或匿名私信。
- 首版不支持一条帖子同时混合视频、音频和图片。
- 不以小程序代码复用为目标，不在 React Native 中引入 Uni-app 页面。

## 7. 关键用户流程

### 7.1 浏览到互动

打开 App → 匿名读取公开 Feed → 进入帖子详情 → 点击点赞/收藏/评论 → 未登录则完成手机验证码登录 → 原动作继续执行。

### 7.2 发布媒体帖子

登录 → 选择媒体类型 → 选择本地文件 → 客户端校验 → 获取上传目标 → 直传对象存储 → 服务端确认媒体 → 填写正文与分类 → 发布 → 首页出现新帖子。

上传成功但发帖失败时，媒体进入临时状态并由后台任务在 24 小时后清理。

### 7.3 跨端继续使用

App 手机号登录并创建内容 → 小程序使用同一手机号登录 → 服务端解析为同一个 `profileId` → 展示相同帖子、收藏和资料。微信快捷登录接入后，首次使用必须绑定已有手机号或明确创建新账号，禁止静默产生重复账户。

## 8. 非功能要求

- 支持基线：iOS 16+、Android 10+；手机竖屏优先，平板可用但不做专门布局。
- Feed 首屏在常规 4G/Wi-Fi 下 2 秒内出现可阅读内容；有缓存时 500ms 内展示旧数据。
- 所有列表采用游标分页，不使用深页 `offset`。
- 上传可取消、可重试；弱网切换不得产生重复帖子。
- 所有私有数据由服务端权限控制，不能只靠前端隐藏。
- 公开文本、图片和视频进入审核流程；用户可举报、拉黑并申请注销。
- 埋点、日志和崩溃信息不得记录验证码、访问令牌或私聊正文。

## 9. MVP 验收标准

- 新用户能在真机完成登录、编辑资料、浏览 Feed、发布图文/视频/音频之一、评论、点赞和收藏。
- 视频慢放和镜像在 iOS/Android 真机均有效；切到后台后音频继续播放并可从锁屏暂停。
- 同一账号重新安装 App 后，服务端内容和收藏仍能恢复。
- 两个账号之间的可见性、删除、拉黑和举报权限有自动化测试覆盖。
- 小程序接入前，使用 API 契约测试证明同一份响应不依赖 React Native 类型或组件。

## 10. 成功指标

上线后按周观察，不把指标写死为发布门槛：次周留存、周人均有效播放次数、媒体帖子发布成功率、内容互动率、上传失败率、播放失败率、举报率和审核处理时长。首个版本优先判断媒体工具是否带来重复使用，而不是追求内容总量。
