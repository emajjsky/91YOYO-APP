# 91YOYO App 现状与路线图

版本：v0.1  
盘点日期：2026-09-15

## 1. 当前进度

| 模块 | UI | 真实数据/能力 | 当前结论 |
| --- | --- | --- | --- |
| 导航与主题 | 已有 | 本地可运行 | 首页、探索、发布、装备、我的和详情路由已接通 |
| 首页 Feed | 已有 | Mock | 点赞/收藏只改 Zustand 内存，重启后丢失 |
| 帖子详情/评论 | 已有 | Mock | 评论展示为静态数据，没有新增评论 API |
| 探索/搜索 | 已有 | Mock | 输入框和分类切换存在，没有真实搜索 |
| 发帖 | 已有 | 占位 | 没有系统选取、上传、持久化和重复提交保护 |
| 视频/音频 | 静态卡片 | 未实现 | 点击仅弹出提示，没有播放、慢放、镜像或后台音频 |
| 装备 | 已有 | Mock | 没有详情、发布、筛选 API 和状态流转 |
| 个人主页 | 已有 | Mock | 设置项大多为提示框，没有真实编辑和隐私保存 |
| 私聊 | 占位 | 未实现 | 路由存在，页面标注 Phase 4 |
| Jam | 占位 | 未实现 | 路由存在，没有地图和位置服务 |
| 后端 | 基础已部署 | 进行中 | 腾讯云 API、PostgreSQL、COS 健康检查和公共 Feed 已跑通 |
| 工程质量 | 基础 | 部分 | TypeScript 严格模式可用；没有 lint、单测、E2E 和 CI |
| 原生工程 | iOS 已生成 | Android 未生成 | `app.json` 仍是 Expo 默认名称和 Bundle Identifier |

结论：当前更接近视觉与交互原型，不是可发布的 MVP。最短路径不是继续补页面，而是先打通“登录 → Feed → 上传 → 发布 → 跨设备恢复”的真实纵向链路。

## 2. 阶段规划

工期取决于人员和后端资源，下面以可验收出口排序，不承诺固定日期。

### Phase 0：工程和后端基线

- 固化正式应用标识、环境变量、开发/预发布/生产环境。
- 建立 API migrations、seed、配置校验和数据库权限测试。
- 建立 App service/repository 层，页面不直接依赖数据库或 COS。
- 补 lint、单测、CI 和错误监控基础。

出口：新环境可按文档初始化；未配置密钥时应用给出明确错误；CI 能阻止类型和测试失败的变更。

### Phase 1：账号与只读 Feed

- 手机验证码登录、会话恢复、退出和基础资料。
- 公开 Feed 游标分页、帖子详情、用户主页。
- 缓存上次成功 Feed，提供加载、空、错误和重试状态。

出口：两个测试账号可跨设备登录并看到一致的服务端数据。

### Phase 2：媒体上传与练习播放器

- 图片、视频、音频选择与客户端校验。
- 临时上传、进度、取消、重试、媒体确认与孤儿文件清理。
- 视频倍速/镜像/循环；音频后台播放和锁屏控制；图片预览。
- 创建、删除自己的帖子和可见性设置。

出口：iOS/Android 真机连续完成 20 次不同媒体发布，不出现重复帖子或无法清理的失败上传。

### Phase 3：社区闭环（App MVP）

- 点赞、收藏、一级评论、关注和拉黑。
- 分类/花式筛选，用户、内容和话题搜索。
- 接入只读装备列表和个人装备柜，复用现有界面但不开放卖家联系。
- 举报入口、基础审核状态、账号注销流程。
- 性能、可访问性、弱网和崩溃治理。

出口：满足 PRD 的 App MVP 验收标准，并产出 TestFlight/Android 内测包。

### Phase 4：装备与私聊（v1.1）

- 装备详情、发布、编辑、预留、下架和成交标记。
- 一对一会话、文本/图片/装备卡片消息、未读数和推送。
- 内容和私聊风控、拉黑后会话限制。

出口：买卖双方可完成“浏览 → 联系 → 线下自行成交 → 标记售出”，不涉及平台资金托管。

### Phase 5：Jam 与正式发布（v1.2）

- 地图浏览、活动发布、报名/取消报名、日历和通知。
- 隐私权限文案、商店素材、发布签名、监控和运营后台最小能力。

出口：通过应用商店审核，位置权限仅在进入地图或选择地点时申请。

### Phase 6：微信小程序接入

- 小程序接入相同手机号账号和 `profileId`。
- 按 API 契约替换硬编码 Store，优先接 Feed、详情、互动和个人资料。
- 适配微信上传、播放、订阅消息和网络域名白名单。
- 验证 App 创建、小程序读取；小程序互动、App 实时/刷新后读取。

出口：核心契约测试在 App adapter 与 Uni-app adapter 上同时通过，不存在端专属字段写入共享表。

## 3. 优先级规则

1. 先保证账号、数据权限和写入幂等，再扩充页面。
2. 先完成一条真实纵向链路，再并行开发装备、私聊和 Jam。
3. 影响 App/小程序共享字段的改动必须先更新 API 契约。
4. 支付、担保和结算是独立项目，不能作为装备模块中的一个普通按钮加入。

## 4. 近期交付顺序

下一阶段实现应按以下顺序拆分：腾讯云短信认证 → token 会话 → 媒体签名上传 → 发布 → 播放器 → 评论互动。每一步都要形成可独立验证的提交。

## 5. 主要风险

| 风险 | 影响 | 处理原则 |
| --- | --- | --- |
| 腾讯云短信签名和模板未配置 | 登录链路无法上线 | Phase 1 完成签名、模板、限流和测试号码验证 |
| 视频转码与内容审核耗时 | 上传成功但长时间不可发布 | 使用明确 processing 状态、异步任务和失败重试，不让客户端假成功 |
| App 标识仍为默认值 | 签名、推送和商店记录后续难迁移 | 生成正式内测包前确认永久 Bundle ID 和 Android package |
| 社区内容与二手交易合规 | 商店审核、投诉和运营风险 | MVP 先建立举报、审核和注销；资金交易作为独立立项 |
| App 与小程序字段实现分叉 | 后续接入受阻 | 契约基于 HTTPS/JSON，两端 adapter 共用版本化 fixtures |
